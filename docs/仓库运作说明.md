# ShadowTrace 仓库运作说明

本文说明 **这个仓库现在如何运转**：它解决什么问题、代码怎么分层、一次调查从告警走到 CLOSED 经过哪些组件、怎么启动与验收。面向导师、答辩听众和后续接手的人。权威规格仍以根目录 [`README.md`](../README.md) 第 1–4 节与 [`ShadowTrace 工程实施拆解方案.md`](../ShadowTrace%20工程实施拆解方案.md) 为准；部署命令以 [`docs/deployment.md`](deployment.md) 为准。

**当前阶段（必须先读）：** 默认闭环仍是 **MockXDRServer + MockToolProvider + Mock Disposition**（`SOURCE_MODE=mock_xdr` / `DISPOSITION_MODE=mock_xdr` / `KIND=mock` / `TOOL_MODE=mock`）。不接入生产时隔离、禁用账号、杀进程与全套 `query_*` 功能完整。挑战杯 OpenAPI 已是 Adapter 合同（`contracts/vendor/sangfor_xdr`、`adapters/sangfor`）；Agent 仍禁止厂商 path。L10 first-contact 剧本存在，本仓库只在 Vendor Wire Mock 上绿过，**不是** live 已验证，不得声称已对接生产 XDR。演示回执带 `simulated=true`，表示 Mock 契约成立。分析正文、报告、Prompt、decision_trace **永不写回** 外部系统。Cutover-Ready ≠ 真机验证。

仓库从 ISSUE-001 起主要由 Cursor Agent 按 GitHub Issue 实现与评审；本文描述的是 **代码里实际存在的运作方式**，不是愿景幻灯片。

---

## 1. 一句话

ShadowTrace 是独立部署的多 Agent 安全运营系统：

接入安全事件 → 分诊 / 取证 / 图谱 / 风险 →（可选）处置计划 → 人审 → 执行 → 写回验证 → 报告 → 仅当外部终态写回 CONFIRMED 才 CLOSED。

它与具体 XDR 厂商、具体大模型厂商解耦：Agent 业务层不绑定深信服私有 API，也不绑定某一 LLM 品牌。换数据源改 Adapter；换模型改 `LLMProvider`。

## 3. 运行时栈

默认 compose（[`infra/docker-compose.yml`](../infra/docker-compose.yml)）：

- PostgreSQL 16 + pgvector（事实库；调查上下文、动作、outbox、回执）
- Redis（lease、Socket.IO、Celery broker/backend）
- Mock XDR（`:8100`，只读源 + 处置写回）
- Backend FastAPI（`:8000`，`/api/v1`）
- Frontend nginx 反代（`:3000`）

可选 profile：

- `worker`：Celery investigation worker（`TASK_MODE=celery`）
- `scheduler`：Beat + 摄入
- `demo`：`make up-demo` = core + worker + scheduler + OTEL/Prometheus/Grafana
- `optional`：OpenSearch / Neo4j（**不是 P0**）

任务模式：

| `TASK_MODE` | 行为 | 用途 |
|-------------|------|------|
| `background`（`make up` 默认） | FastAPI BackgroundTasks，进程内 | 短路径分析；重启丢任务 |
| `celery`（`make up-demo`） | Worker 跑 `run_investigation` | **官方全闭环金路径** |

LLM：

| `LLM_MODE` | 行为 |
|------------|------|
| `mock`（默认） | MockLLM + 场景金包，可复现、无需密钥 |
| `openai_compatible` | 任意兼容 API（如 glm）；Agent 仍走同一 `LLMProvider` |

Live 安全栅栏默认全关：`ALLOW_LIVE_SIDE_EFFECTS=false`、`ALLOW_XDR_WRITEBACK=false`、`BLOCK_LIVE_ACTION_EXECUTION=false`（后一项为冻结开关，打开会挡住 Mock `execute_plan`，演示不要开）。存在 `.env.live` 或误开 live 开关时，`make up-demo` **fail-closed**。

## 4. 必须分清的概念

这些是答辩最容易讲混的地方。

1. **`EventStatus` ≠ `FinalVerdict`**  
   状态是编排进度（new → triaging → … → closed）。判定是标签（`confirmed_threat` / `false_positive` 等）。高置信误报事件仍经合法路径 CLOSED，不会把「误报」当成一种 EventStatus。

2. **本地 Action SUCCESS ≠ 外部已写回**  
   工具/XDR_MANAGED 执行成功只说明 ShadowTrace 侧动作完成。外部是否认账看 `DispositionReceipt`（`WritebackStatus`、`confirmation_evidence`、`simulated`）。

3. **`writeback_required` ≠ `writeback_readiness` ≠ outbox ≠ 回执**  
   业务要不要写回、现在能不能提交、本地队列送到哪、外部回了什么，四套正交字段。UI 不得混成一个绿灯。

4. **分析永不写回；处置必须写回（required 事件）**  
   报告/研判不出站。`disposition_policy=required` 时，本周期必须有且仅有一条 deferred 的 `update_source_event_disposition`（`EVENT_STATUS_UPDATE`）在 Adapter 上 **CONFIRMED**，才能 CLOSED。

5. **`include_response_execution` 默认 false**  
   HTTP「触发研判」默认只分析到报告。全闭环 demo/评测会显式打开响应执行。

6. **Mock `simulated=true` 可以通过 CLOSED**  
   这是 P0 演示合同（ISSUE-345/351），scorecard 必须写 `writeback=simulated`，禁止对外说成 live 已验证。

## 5. 一次调查怎么走

```mermaid
flowchart TD
  ingest[SourceIngester 入库] --> event[SecurityEvent NEW]
  event --> http[POST investigate]
  http --> celery{TASK_MODE}
  celery -->|background| sa[SuperAgent.investigate]
  celery -->|celery| worker[Celery run_investigation]
  worker --> sa
  sa --> graph[LangGraph workflow_graph]
  graph --> triage[TriageAgent]
  triage --> planner[PlannerAgent]
  planner --> evidence[EvidenceAgent]
  evidence --> fp[FP 裁决]
  fp --> rag[可选 RAG]
  rag --> gnode[GraphAgent]
  gnode --> risk[RiskAgent]
  risk --> resp{include_response?}
  resp -->|否| report[ReportAgent]
  resp -->|是| response[ResponseAgent]
  response --> appr[审批]
  appr --> exec[ActionExecution]
  exec --> verify[VerifyAgent]
  verify --> wb[DispositionSync outbox]
  wb --> report
  report --> closeGate{required 且终态 CONFIRMED?}
  closeGate -->|是| closed[EventStatus CLOSED]
  closeGate -->|否| reporting[停在 REPORTING / 人工]
```

对应代码入口：

- 摄入：[`backend/app/ingestion/source_ingester.py`](../backend/app/ingestion/source_ingester.py)
- HTTP：[`backend/app/api/v1/events.py`](../backend/app/api/v1/events.py) `investigate_event`（约 1392 行起），会拿调查 lease 并传 `owner_id`
- 编排：[`backend/app/agents/super_agent.py`](../backend/app/agents/super_agent.py) `investigate()`
- 图：[`backend/app/orchestration/workflow_graph.py`](../backend/app/orchestration/workflow_graph.py)  
  节点包括 triage、planner、evidence、fp_adjudication、graph、risk、response、approval、execute、verify、report、close 等
- 写回：DispositionSync + outbox；关闭门在状态机（simulated 收据、确认证据等级、side-effect 收敛）

两条常见剖面：

| 剖面 | 怎么触发 | 终态 |
|------|----------|------|
| 分析-only | `include_response_execution=false` 或 `ORCHESTRATION_MODE=analysis_only` | REPORTING，无处置/写回 |
| 生产图全闭环 | demo-full-loop / adversarial full-loop，`include_response_execution=true` | 审批 → 执行 → 验证 → 写回 CONFIRMED → CLOSED |

L2/L3 动作默认进审批队列；前端 `/approvals` 或评测脚本批准。**不要空等 `APPROVAL_TIMEOUT`。**

## 6. 数据与持久化

调查过程写 PostgreSQL（Alembic 当前 head 含 `graph_resume_intent` 等）。典型表群：

- 事件、审计日志、上下文 journal
- `action` / `action_execution_job` / `action_target_result`
- `disposition_outbox` / `disposition_receipt`
- `agent_trace` / `llm_call_log`
- `investigation_intent`（Celery/HTTP 耐用意图）
- 知识、playbook、检测治理（扩展能力）

Redis：lease（防并发双跑）、实时推送、Celery。前端列表/详情靠 Socket.IO 局部刷新，断线则轮询。

WorkingMemory 有字段所有权：非 owner Agent 不能乱写上下文键。

## 7. 前端如何配合后端

详情页 Tab 固定为：`source`、`timeline`、`graph`、`evidence`、`actions`、`writeback`、`audit`、`report`（可选 `chat`）。这是给分析员看的「同一事件的多个投影」，不是另一套状态机。

写回 Tab 必须展示 Adapter 回执，并在 Mock 下标 **模拟回执**。本地动作成功或一次 HTTP ACK 不能当成「已写入 XDR」。

看板 `/dashboard` 的「写回确认率」统计的是回执，不是 Action SUCCESS 计数。

## 8. 怎么把系统跑起来

官方演示（Celery worker，可 CLOSED）：

```bash
# 不要留着 .env.live 再 up-demo
make down-v
make up-demo
make demo-full-loop
# 浏览器 http://localhost:3000
```

适合录屏、能停在审批的分步路径：

```bash
make up-demo
make bootstrap-demo-full-loop    # 停在 waiting_approval
# 在 UI /approvals 批准
EVAL_REQUIRE_CLOSED=1 make eval-full-loop
```

仅分析种子（**不会** CLOSED）：

```bash
make up-demo && make bootstrap-demo && make smoke-demo
```

短路径（无 worker，非金路径）：

```bash
make up && make bootstrap
```

健康检查：`GET /api/v1/health`。Playbook 未就绪时 demo 的 health 可为 503（`PLAYBOOK_REQUIRED=true`）。

用真模型做对抗全链路（需 Postgres/Redis，仍 Mock XDR）：

```bash
cd backend
export LLM_MODE=openai_compatible
export LLM_PRIMARY_MODEL=glm-5.2   # 或其它兼容模型
export ALLOW_LIVE_SIDE_EFFECTS=false ALLOW_XDR_WRITEBACK=false
uv run --frozen python -m pytest \
  tests/adversarial/test_agent_adversarial_full_loop.py -m adversarial_audit -v -s -o addopts=
```

密钥只放环境变量，不要提交 `.env.live`。

## 9. 测试与 CI 怎么卡质量

| 层 | 作用 |
|----|------|
| `backend/tests/` 默认 pytest | 单测 + 集成；`pyproject.toml` addopts 排除 `adversarial_audit` / `nightly` / `system` 等 |
| `tests/adversarial/` | 动态对抗场景；Live LLM 时评 verdict / 封禁覆盖 / `simulated` 认证语言 |
| `make check-contract-drift` | OpenAPI 与实现漂移则 CI 红 |
| `.github/workflows/ci.yml` | lint（ruff/mypy）、backend-test、closure-gates-mock、system、docker-build、契约 |
| `celery-worker-nightly.yml` | 重投递矩阵；应对空库先 `alembic upgrade` |

改 API schema 必须 `make update-contracts`。改枚举/核心表/error_code 必须更新对应快照测试（ISSUE-368 一类门禁）。

质量评分（OutputQuality、ISSUE-334 文本理解）默认 **不阻断 CLOSED**（`OUTPUT_QUALITY_BLOCKING=false`）。对抗场景故意用不含 IOC 字面量的告警标题：title 理解分可以为 0，同时 source 投影仍能找齐实体——这是评测诚实，不是漏检。

## 10. 工程是怎么「用 AI 做出来的」

工作方式不是一次生成整个产品，而是：

1. 方案文档拆成 `ISSUE-XXX`（目标、文件范围、统一命名、验收、禁止事项）。
2. Agent 按 [`docs/AI_ISSUE_EXECUTION_PROMPT.md`](AI_ISSUE_EXECUTION_PROMPT.md) **一次只做一单**。
3. 另一套 [`docs/AI_CODE_REVIEW_PROMPT.md`](AI_CODE_REVIEW_PROMPT.md) 做评审。
4. CI + Mock 金路径 +（可选）Live glm 对抗链路做回归。

因此目录里会看到大量 `ISSUE-nnn` 注释：那是合同锚点，不是噪音。后续人改代码时，优先读当前 Issue 与简介第 4 节，不要无故推翻已冻结语义（尤其写回、CLOSED 门、Mock simulated、lease/`owner_id`）。

## 11. 现在能演示什么、不能声称什么

**可以演示（Mock 契约）：**

- 事件接入与列表实时更新
- 多 Agent 调查与 15 章报告
- 人审队列与批准后继续执行
- 动作执行、验证、写回 CONFIRMED、事件 CLOSED
- 详情上源对象 / 证据 / 图谱 / 审计分离展示
- 看板与工具审计

**不能声称：**

- 已对接生产深信服 XDR 或已 live 验证写回
- 本地 Action SUCCESS 等于外部系统完成
- Mock `readback_verified` 等于真实回读
- Vendor Wire Mock / L10 脚本绿等于生产联调
- Layer 8b Query Provider 未接线（live 调查 query 另开）
- `make up` 短路径等于官方 CLOSED 金路径

**明确未作为 P0 的：** 生产 XDR 联调、Layer 8b live 调查 Query Provider、DSP 自动写回、Neo4j/OpenSearch、完整检测/UEBA 自治（有表和部分服务，不挡演示闭环）。Adapter 代码与开放列表合同已在仓库；P0 合格标准仍是 Mock 金路径。
